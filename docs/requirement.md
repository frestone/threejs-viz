# Three.js Viz 产品需求说明

## 1. 文档目的

本文档定义 Three.js Viz 的产品目标、用户场景、功能需求、质量要求和验收标准。本文档仅描述产品需要提供的能力与预期结果，不规定技术架构、代码结构或具体实现方式。

## 2. 产品定位

Three.js Viz 是面向自动驾驶离线数据的三维可视化与回放产品，帮助研发、测试和数据分析人员加载行车数据，观察自车、地图、规划、感知、预测及传感器信息，并通过时间轴和图层控制定位问题。

### 2.1 核心目标

1. 支持离线自动驾驶数据的快速加载、回放与检索。
2. 准确展示车辆、环境、算法输出和传感器数据。
3. 支持不同数据规格、地图模式和使用环境。
4. 提供一致的浏览器端与桌面端使用体验。
5. 在长时、大数据场景下保持流畅、稳定和可控的资源占用。

### 2.2 非目标

1. 不提供自动驾驶算法训练、编辑或在线控制能力。
2. 不提供原始数据生产、标注或修复能力。
3. 不替代专业视频编辑、地图制作或数据管理平台。
4. 本阶段不要求用户自行编写可视化程序。

## 3. 目标用户

- 自动驾驶算法研发与调试人员。
- 系统测试、数据质量和问题定位人员。
- 需要查看或交付离线可视化结果的平台开发人员。

## 4. 典型用户场景

1. 用户选择本地数据文件并开始分析。
2. 用户按名称打开可访问的在线数据文件。
3. 用户播放、暂停、调整倍速或拖动到指定时刻。
4. 用户切换地图、规划、感知、预测等图层。
5. 用户查看图像、点云、原始通道数据及趋势图表。
6. 用户在浏览器或桌面应用中完成相同的分析流程。

## 5. 功能需求

### FR-01 数据加载与识别

- **FR-01-01** 产品应支持加载本地 MCAP 数据文件。
- **FR-01-02** 产品应支持加载部署环境允许访问的在线数据文件。
- **FR-01-03** 产品应自动识别受支持的数据模式，无需用户手工选择解析方式。
- **FR-01-04** 加载过程中应向用户展示明确的状态反馈。
- **FR-01-05** 加载失败时应展示可理解、可定位的错误信息。
- **FR-01-06** 用户应能浏览其有权访问的云端 S3 存储空间中的 MCAP 文件。
- **FR-01-07** 用户应能从云端浏览结果中选择并加载目标 MCAP 文件；无权限、无结果或访问失败时，产品应提供明确提示。

### FR-02 数据兼容与配置

- **FR-02-01** 产品应支持不同供应商的数据主题、字段和展示规则。
- **FR-02-02** 产品应支持高精地图和轻量地图数据模式。
- **FR-02-03** 产品应允许通过配置扩展图层、通道、类型名称和展示样式。
- **FR-02-04** 同一类数据在不同文件中的展示含义应保持一致。
- **FR-02-05** 配置缺失或不兼容时应明确提示，不得静默展示错误结果。
- **FR-02-06** 数据传输所依赖的内容协议应保持通用与可扩展，能够以配置方式描述新主题、新字段与新样式，而无需为特定业务定制专用协议。

### FR-03 三维场景展示

- **FR-03-01** 产品应展示自车位置、姿态和行驶方向。
- **FR-03-02** 产品应展示地图、规划、感知和预测等业务图层。
- **FR-03-03** 产品应支持点、线、框、面、文字、箭头和规划轨迹等表达形式。
- **FR-03-04** 障碍物的位置、尺寸、方向、类型和颜色应准确可辨。
- **FR-03-05** 用户应能旋转、缩放、平移视角，并可选择跟随自车。

### FR-04 坐标与时序准确性

- **FR-04-01** 不同坐标系的数据应在场景中正确对齐。
- **FR-04-02** 传感器相对数据应结合有效标定信息显示在正确位置。
- **FR-04-03** 障碍物位置、轮廓和朝向应使用一致的空间基准。
- **FR-04-04** 数据采样时刻不一致时，展示结果不得出现明显的整体漂移或偏航。
- **FR-04-05** 标定缺失、无效或不匹配时应向用户提示。

### FR-05 播放与时间轴

- **FR-05-01** 用户应能播放、暂停、调整播放倍速和拖动时间轴。
- **FR-05-02** 时间轴应显示总时长、当前时间和当前可访问范围。
- **FR-05-03** 拖动后应尽快展示目标时刻附近的数据。
- **FR-05-04** 播放进度与三维画面应保持一致，不得出现进度持续前进而画面长期冻结。
- **FR-05-05** 用户主动跳转的目标不得被自动播放行为覆盖。

### FR-06 图层与数据通道

- **FR-06-01** 图层面板应按数据内容动态展示可用分组和子项。
- **FR-06-02** 用户应能单独或批量控制图层显隐。
- **FR-06-03** 产品应按需启用图像、点云和原始数据通道。
- **FR-06-04** 启用通道后，应展示当前时间附近的可用内容。
- **FR-06-05** 关闭通道后，相关内容应停止更新并从界面中隐藏。
- **FR-06-06** 用于控制可视化内容可见性的分层复选框树应由服务端提供。
- **FR-06-07** 分层复选框树应统一包含三维图形和二维图表，并支持按父级、分组及单项控制可见性。
- **FR-06-08** 前端应允许用户修改分层树中的可见状态和可视化项。
- **FR-06-09** 用户基于自定义通道和参数新增的三维渲染对象或二维图表，应能加入分层树并接受统一的可见性控制。

### FR-07 图像、点云、原始数据与图表

- **FR-07-01** 产品应展示数据文件中可用的图像通道，并允许独立开关。
- **FR-07-02** 产品应展示可用点云，并保留颜色、强度等有效属性。
- **FR-07-03** 产品应允许查看受支持的原始数据内容及其基本元信息。
- **FR-07-04** 产品应根据数据内容动态提供可用图表。
- **FR-07-05** 图表应随当前播放时间更新，并支持独立查看。
- **FR-07-06** 用户应能自定义目标通道和参数，不受预配置通道列表限制。
- **FR-07-07** 用户应能选择自定义参数的前端展示方式，包括三维图形或二维图表。
- **FR-07-08** 产品应校验用户指定的通道和参数；目标不存在、数据类型不受支持或数据不可用时，应提供明确提示。
- **FR-07-09** 用户应能自行选择要显示的数据主题（topic），不受预置显示列表限制。
- **FR-07-10** 用户应能选择所选主题中要显示的具体字段，并指定字段在三维或二维视图中的展示样式。
- **FR-07-11** 用户对显示主题、字段和样式的选择应可保存与复用，并在同类数据文件中保持一致的展示结果。
- **FR-07-12** 用户应能选择任一可用主题（topic），实时查看其原始数据经解码后的文本内容（即原始 protobuf 数据转换为 JSON 后的可读文本；由前端对后端下发的原始序列化字节进行解码，后端不额外转换为文本）。
- **FR-07-13** 原始数据文本应随播放推进动态更新，实时反映当前播放时间对应的最新消息内容。
- **FR-07-14** 用户应能输入关键字对原始数据文本进行查找，查询结果应能定位或高亮匹配位置；在实时播放过程中，若已输入查询关键字，查询结果应随文本更新而实时刷新。
- **FR-07-15** 原始数据文本应支持分页展示，避免单条消息或长文本一次性渲染导致界面卡顿。
- **FR-07-16** 原始数据应支持按 JSON 结构以树状层级展示，允许用户展开、折叠嵌套字段，并可在文本视图与树状视图之间切换。

### FR-08 产品形态与交付

- **FR-08-01** 产品应同时提供浏览器版本和 Linux 桌面版本。
- **FR-08-02** 两种版本的核心功能、数据含义和交互行为应一致。
- **FR-08-03** 桌面版本安装后应可独立启动并使用本地文件。
- **FR-08-04** 产品启动失败或必要服务不可用时应给出明确提示。
- **FR-08-05** 发布包应包含正常运行所需的全部产品资源。
- **FR-08-06** 桌面版本应作为单一应用交付，用户无需另行安装、配置或手动启动独立的后端服务即可完成全部分析流程。
- **FR-08-07** 浏览器版本与桌面版本在数据加载、协议内容和可视化结果上应保持一致，部署形态的差异不得改变用户可见的功能与数据含义。

## 6. 非功能需求

### NFR-01 性能与容量

- **NFR-01-01** 常规场景下播放和交互应保持流畅。
- **NFR-01-02** 长时数据回放期间，内存占用应有明确上限且不得持续无界增长。
- **NFR-01-03** 大规模几何、图像或点云数据不应导致界面长时间无响应。
- **NFR-01-04** 产品应展示必要的播放、缓存和渲染状态，便于用户判断运行情况。

### NFR-02 稳定性与可靠性

- **NFR-02-01** 切换文件、跳转时间、断线恢复后不得混入旧数据。
- **NFR-02-02** 长时间播放、频繁跳转和反复切换图层时应保持稳定。
- **NFR-02-03** 关闭文件或退出应用后，相关资源应被及时释放。
- **NFR-02-04** 单个不支持的数据通道不得导致整个文件无法使用。

### NFR-03 易用性、兼容性与安全

- **NFR-03-01** 主要操作应有明确标签、状态和反馈。
- **NFR-03-02** 产品应支持主流现代浏览器及目标 Linux 桌面环境。
- **NFR-03-03** 本地路径、在线访问凭证及其他敏感信息不得暴露给无关客户端或用户。
- **NFR-03-04** 产品扩展新数据类型时，不应改变已有数据的用户操作方式。

## 7. 验收标准

- **AC-01** 至少一份高精数据和一份轻图数据可成功加载并正确展示。
- **AC-02** 自车、地图、规划、感知和预测图层可正确显示与切换。
- **AC-03** 车辆转弯过程中，障碍物位置和朝向无明显整体偏移。
- **AC-04** 播放、暂停、倍速和不同位置的时间跳转均工作正常。
- **AC-05** 播放进度与画面一致，正常播放时画面不会长期冻结。
- **AC-06** 图像、点云和原始数据通道可按需开启和关闭。
- **AC-07** 长时间播放时资源占用受控，应用无明显持续劣化或崩溃。
- **AC-08** 浏览器版与桌面版的核心功能和交互结果一致。
- **AC-09** Linux 桌面发布包安装后可独立启动并加载本地文件。
- **AC-10** 数据不兼容、加载失败或服务异常时，用户能看到明确错误提示。
- **AC-11** 用户可浏览并加载其有权访问的云端 S3 MCAP 文件，访问异常时可获得明确提示。
- **AC-12** 服务端提供的分层复选框树可统一控制三维图形、二维图表和用户自定义项，父子层级的可见性控制结果正确。
- **AC-13** 用户可自定义要显示的主题、字段和样式，选择结果能正确应用于三维或二维视图，并可保存后在同类文件中复用。
- **AC-14** 桌面版本安装后可作为单一应用启动并完成全部分析流程，无需用户单独启动后端服务；其功能与数据结果与浏览器版本一致。
- **AC-15** 用户可选择某一主题实时查看其原始数据 JSON 文本，文本随播放动态更新；输入关键字可查找并在播放中实时刷新结果；文本支持分页，且可按 JSON 结构以树状视图展开折叠并切换视图。

## 8. 范围外与待确认事项

1. 尚未支持的数据类型，其产品优先级和展示方式需另行确认。
2. 在线文件检索、权限与凭证管理范围需结合部署环境确认。
3. 性能验收所使用的数据规模、目标设备和量化阈值需另行确定。
4. 原始数据的可视化格式范围需按实际用户场景确认。
